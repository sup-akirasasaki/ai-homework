# チーム日程調整

## 何のためのアプリか

5人程度のメンバーで、打ち合わせの日程を決めるためのアプリです。
候補日時ごとに各メンバーの都合（○／△／×）を幹事がまとめて入力します。
全員の都合が一番よい候補が、画面上部にひと目で表示されます。

## 公開URL

https://sup-akirasasaki.github.io/ai-homework/

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体です。画面・見た目・動き（JavaScript ※1）を、すべてこの1ファイルに入れています |
| `robots.txt` | 検索エンジンのロボット（ネット上のページを自動で集めて回るプログラム）に「このサイトを見に来ないで」と伝えるファイル |
| `_headers` | 公開サービス（Netlify・Cloudflare Pages）に「検索結果に載せない」という指示（X-Robots-Tag ※2）を付けてもらう設定ファイル |
| `README.md` | このファイル（説明書） |

※1 JavaScript：ブラウザの中で動くプログラムの言語です。FileMaker のスクリプトに相当します。
※2 X-Robots-Tag：ページと一緒に送られる「検索エンジン向けの注意書き」です。

検索エンジンに載せないための設定は、次の3か所に入れています。

1. `index.html` の robots メタタグ（ページ内に書いた注意書き）
2. `robots.txt`
3. `_headers` の X-Robots-Tag

## 使い方

### 開き方

- **自分のPCで試す**：`index.html` をダブルクリックすると、ブラウザで開きます。
- **公開後**：上の「公開URL」を開きます。

初めて開いたときは、架空の候補日が4件入っています。
日付は「開いた日の3日後〜12日後」で自動的に作られます。

### 画面の見方

- **上部のサマリー**：会議名と、いちばん都合のよい候補を表示します。
  - 選び方：「○の数が多い順 → ○が同じなら△が多い順 → それも同じなら日時が早い順」
  - 状態が「決定」の候補があるときは、そちらを「決定した日程」として表示します。
- **候補日の一覧**：日付の早い順に並びます。
  - PC（画面の幅 768px 以上）：表で表示します。行＝候補日、列＝メンバー、右端が○の数です。
  - スマホ：カードで表示します。
  - ★ の付いた候補が、いちばん都合のよい候補です。
- 記号の意味：○ 参加できる ／ △ 調整すれば参加できる ／ × 参加できない ／ － 未回答

### 操作手順

1. **会議名とメンバー名を設定する**
   - 右上の［設定］を押します。
   - 会議名と、メンバー5人の名前を入力して［保存］を押します。
   - 名前を変えても、入力済みの回答はそのまま残ります。回答は「何番目の人か」で記録しているためです。FileMaker の繰り返しフィールドと同じ考え方です。
2. **候補日を追加する**
   - ［＋ 候補日を追加］を押します。
   - 日付・開始時刻・終了時刻を入力します。
   - メンバーごとに ○／△／× のボタンを押し、［保存］を押します。
   - 選んでいるボタンをもう一度押すと「未回答」に戻ります。
3. **候補日を編集する**
   - PC では表の行を、スマホではカードを押します。
   - 同じポップアップ（画面の上に重なって出る小窓）が開くので、内容を変えて［保存］を押します。
4. **日程を決定する**
   - 編集ポップアップで、状態を「決定」にして保存します。
   - 「決定」にできるのは1件だけです。別の候補を「決定」にすると、前に決定していた候補は自動で「候補」に戻ります。
5. **候補日を削除する**
   - 編集ポップアップの［削除］を押します。確認が出るので［OK］を押します。
6. **最初の状態に戻す**
   - ［ダミーデータに戻す］を押します。確認が出るので［OK］を押します。
   - 候補日・会議名・メンバー名が、すべて初期状態に戻ります。

## 注意事項

- **データは、開いたそのブラウザの中にだけ保存されます**（localStorage ※3）。
  - ほかの人とは共有されません。
  - 別のPC・スマホ、別のブラウザ（例：Chrome と Safari）でも共有されません。
  - ファイルをダブルクリックで開いた場合と、公開URLで開いた場合も、別々のデータになります。
  - ブラウザの「閲覧履歴データの削除」などでサイトのデータを消すと、入力内容も消えます。
  - プライベートモード（履歴を残さない閲覧方法）では、保存されないことがあります。
- **入っているデータはすべてダミー（架空のもの）です**。実在の会社名・人名・案件名は使っていません。
  ご自身で入力するときも、実在の名前や社外秘の情報は入れないでください。
- APIキー・パスワードなどの鍵は一切使っていません。
- 見た目の部品（Tailwind CSS ※4）はインターネットから読み込んでいます。オフラインでは見た目が崩れます。
- 開発者ツール（F12キーで開く、エラー確認用の画面）に、Tailwind の「本番環境では使わないでください」という英語の警告が出ることがあります。手軽に使えるお試し版を使っているためで、動作には影響しません。
- このアプリは GitHub Pages（GitHub の無料公開機能）で公開します。そのため、検索除外の3か所のうち2か所は効きません（詳しくは「課題の要件との違い」）。
- 無料プランの GitHub Pages は、リポジトリ（GitHub 上の保管場所）を「公開」にする必要があります。そのため、このフォルダのファイルは誰でも見られる状態になります。鍵や個人情報は入れていません。
- 日付・時刻の入力欄の見た目は、ブラウザや端末ごとに違います（ブラウザ標準の部品を使っているため）。

※3 localStorage：ブラウザの中にある、サイトごとの小さな保存場所です。
※4 Tailwind CSS：見た目（色・余白・文字サイズなど）を手軽に整えるための部品集です。CDN（部品を配信してくれるサーバー）から、バージョン 4.1.11 に固定して読み込んでいます。

### 困ったとき

- **画面が真っ白／ボタンが反応しない**
  - F12 キーで開発者ツールを開き、「Console（コンソール）」タブの赤い文字を確認してください。
- **「日付の入力が途中です」と出て保存できない**
  - 日付欄の年・月・日のどれかが空いています。
  - 3つともすべて入力するか、欄を押すと出るカレンダーから選んでください。
- **データを完全に消したい**
  - ［ダミーデータに戻す］を使ってください。

## 課題の要件との違い

### 検索除外の3か所のうち、2か所が効かない

公開先を GitHub Pages にしたため、検索除外の3か所のうち、確実に効くのは1か所だけです。
3つのファイルはすべて要件どおり作成し、そのまま置いています。

| 場所 | GitHub Pages での効果 | 理由 |
|---|---|---|
| `index.html` の robots メタタグ | **効く** | ページの中に書いてあるため、どこで公開しても有効 |
| `robots.txt` | 効かない | 検索エンジンは「サイトの一番上の階層」（`https://アカウント名.github.io/robots.txt`）しか見ない。このアプリは一段下の階層（`/リポジトリ名/`）に置かれるため、読まれない |
| `_headers` の X-Robots-Tag | 効かない | Netlify・Cloudflare Pages 専用の設定ファイルで、GitHub Pages は読み込まない |

- 公開先を GitHub Pages にした理由：作者の判断です。
- それでも問題がない理由：robots メタタグがあれば、多くの検索エンジンは検索結果に載せません。また、このアプリにはダミーデータしか入っていません。

### 細かい動きの決め方

要件に書かれていなかった細かい動きは、作成前の確認で次のように決めました（すべて推奨案を採用）。

| 項目 | 決めた内容 | 理由 |
|---|---|---|
| ○も△も同じ数のとき | 日時が早い候補を優先 | 決まりがないと表示が安定しないため |
| 「決定」の件数 | 1件だけ。ほかの決定は自動で「候補」に戻す | サマリーに表示する決定が1つに定まるようにするため |
| 新規登録時の日付 | 今日の日付を最初から入れておく（あとから修正） | 日付欄が空だと、年・月・日の一部が空いたままになりやすく、保存できない不具合が起きたため |
| 新規登録時の回答 | 全員「未回答」から始める。選択中のボタンを再度押すと未回答に戻る | 入力ミスを取り消せるようにするため |
| ダミーデータの日付 | 初めて開いた日の数日後〜2週間後 | 固定の日付だと、時間が経つと過去の日付になるため |
| 会議名の初期値 | 「定例ミーティング」 | 架空の一般的な名前にするため |
| 確認ダイアログ | ブラウザ標準の確認画面（OK／キャンセル） | 簡単で確実なため |
| 削除ボタンの場所 | 編集ポップアップの中だけ | スマホでの押し間違いを防ぐため |
| 「ダミーデータに戻す」の範囲 | 候補日・会議名・メンバー名のすべて | 完全に最初の状態へ戻せるようにするため |
| 入力チェック | 終了時刻は開始時刻より後のみ可。同じ日時の重複は可 | 時刻の逆転だけは明らかな誤りのため |
| 作成日時・更新日時 | 編集ポップアップの下に小さく表示 | 一覧を見やすく保つため |
| PC表示とスマホ表示の切り替え | 画面の幅 768px | タブレット縦向きくらいの幅で切り替えるため |
| ○の数 | データとしては保存せず、表示のたびに数える | FileMaker の非保存の計算フィールドと同じ考え方。テーブルは1つのまま |
